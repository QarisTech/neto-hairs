NETO HAIRSNetlify setup

Connect your store backend.

Your store address is netohairs.netlify.app. Your GitHub account is already connected as QarisTech. This page explains the remaining account setup; it does not configure those accounts automatically.

  1. Create a database in Turso, using an available free plan. Save its URL and private database token.

  2. Download the full backend source and extract it. Run commerce/bootstrap.sql in your database's SQL editor, or use the setup command in README_NETLIFY.md.

  3. Create a private neto-hairs repository in your existing GitHub account and upload the extracted source contents. Keep netlify.toml and package.json at the repository root. Connect the repository to your existing Netlify project. This package requires a Git-based/CLI deployment; do not upload it to Netlify Drop.

  4. In Netlify environment settings, set these for the Functions runtime, then redeploy:

    NameValue
    SITE_URLhttps://netohairs.netlify.app
    LIBSQL_DATABASE_URLYour database URL
    LIBSQL_AUTH_TOKENYour private database token
    OWNER_EMAILjessicanetochukwu@gmail.com
    OWNER_PASSWORD_HASHGenerate with the helper below
    CHECKOUT_ENABLEDfalse
    REFUNDS_ENABLEDfalse

    Open browser-only password helper

    Do not paste passwords, tokens or secret keys into chat or GitHub.

  5. Open the owner dashboard after deployment. Confirm products, real prices, available stock and delivery rates. All new products start as enquiry-only.

  6. Then configure your Paystack TEST secret and webhook at https://netohairs.netlify.app/api/paystack/webhook. Use the detailed test procedure in README_NETLIFY.md before turning on live sales.

What is ready?

Code for enquiries, customers, product/stock management, orders, Paystack checkout/webhooks, tracking, returns/refunds, suppliers/purchases, staff permissions, activity and exports. Fifteen backend tests passed locally. Your current Netlify site still serves the static preview until you connect and deploy this backend.

Transactional email requires a verified sender and optional Resend configuration. Courier tracking is manual entry for now. The README lists all deployment prerequisites and current limits.
